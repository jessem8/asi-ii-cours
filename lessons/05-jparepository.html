5. JpaRepository

Tu écris une interface vide. Spring écrit la classe au démarrage. Tu n'écris pas le SQL.

JpaRepository. Le travail à faire : le package repository, une interface par entité, après les associations.

0 sur 0

Avant de commencer : qu'est-ce qu'un repository ?

Imagine une bibliothèque. Bloc est une fiche, MySQL est l'armoire, et BlocRepository est le guichet qui sait chercher ou ranger les fiches.

1. Comprends cette déclaration

public interface BlocRepository extends JpaRepository<Bloc, Long> {
}

Bloc est l'entité. Long est le type de l'identifiant idBloc. Pour une classe Reservation dont l'ID est String, écris JpaRepository<Reservation, String>.

Pourquoi une interface vide ? Spring Data fabrique son implémentation à l'exécution. Tu n'écris pas toi-même les méthodes SQL, et tu ne fais pas new BlocRepository().

3. Optional, expliqué simplement

Un Optional est une boîte qui contient peut-être un Bloc. Si le bloc 99 n'existe pas, la boîte est vide.

Optional<Bloc> resultat = blocRepository.findById(99L);
if (resultat.isPresent()) {
    System.out.println(resultat.get().getNomBloc());
} else {
    System.out.println("Bloc introuvable");
}

Le TP utilise parfois .get() sans vérifier. Sur une boîte vide, cela déclenche une exception. Dans une API soignée, un objet introuvable conduit plutôt à 404 Not Found.

4. Question rapide

Tu veux la liste de tous les blocs : quelle méthode appelles-tu ?

blocRepository.findAll(). La liste peut ensuite être renvoyée par le service.
package tn.esprit.tpfoyer.repository;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;
import tn.esprit.tpfoyer.entity.Bloc;

@Repository
public interface BlocRepository extends JpaRepository<Bloc, Long> {
}

Bloc est l'entité. Long est le type de idBloc. Pour Reservation, le deuxième type est String, parce que idReservation est un String.

Ces méthodes existent déjà. Tu les appelles depuis le service :

  • findAll() lit toutes les lignes.
  • findById(id) lit une ligne. Le cours appelle .get() dessus.
  • save(bloc) effectue une insertion ou une mise à jour selon l'état de l'entité ; l'ID n'est pas le seul critère.
  • deleteById(id) supprime la ligne.

Pour cette première mise en pratique, concentre-toi sur les quatre opérations ci-dessus. Les requêtes personnalisées pourront venir après.

Dans le code simplifié du TP, si l’identifiant n’existe pas, findById(id).get() lance une exception non gérée, ce qui produit généralement HTTP 500. Dans une vraie API, on gère l’absence et on renvoie plutôt HTTP 404.
