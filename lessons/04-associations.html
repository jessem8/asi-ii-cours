4. Associations

Deux questions : combien d’objets sont liés ? Et quel côté possède la relation ? mappedBy indique le côté inverse, pas systématiquement le « fils ».

Associations. Dans le compte rendu : Foyer est le fils de Universite. Etudiant est le fils de Reservation.

0 sur 0

Cardinalité ≠ direction

Cardinalité répond à « combien ? » : 1:1, 1:N, N:1 ou N:N. Direction répond à « quelle classe connaît l'autre ? ».

Un seul sens : A référence B, mais B ne référence pas A. Deux sens : A référence B et B référence A. Les quatre cardinalités peuvent être unidirectionnelles ou bidirectionnelles.

RelationUn seul sensDeux sens
1:1Universite → FoyerUniversite ↔ Foyer
1:NChambre → RéservationsFoyer ↔ Blocs
N:1Bloc → FoyerBloc ↔ Foyer
N:NReservation → ÉtudiantsReservation ↔ Étudiant

mappedBy en une phrase

mappedBy = "foyer" signifie « le côté propriétaire utilise un champ Java qui s'appelle foyer ». Ce n'est pas le nom d'une table SQL. Le mot mappedBy apparaît sur le côté inverse d'une relation bidirectionnelle, jamais sur @ManyToOne.

En 1:N bidirectionnel, Bloc.@ManyToOne garde la clé étrangère ; Foyer.@OneToMany(mappedBy = "foyer") est inverse. En N:N, le propriétaire définit la table de jointure. @JsonIgnore évite ici une récursion JSON, mais ne choisit pas le propriétaire JPA.

Les quatre exemples donnés dans le TP

Un vers un, dans les deux sens. Universite possède foyer. Foyer a mappedBy = "foyer" et @JsonIgnore. La clé foyer_id_foyer est dans la table universite.

// Universite, le propriétaire
@OneToOne
private Foyer foyer;

// Foyer, le fils
@OneToOne(mappedBy = "foyer")
@JsonIgnore
private Universite universite;

Un vers plusieurs, dans les deux sens. Bloc est le côté « plusieurs » et possède la clé étrangère avec @ManyToOne. C’est la collection de Foyer qui déclare mappedBy. Pas de table de jointure.

// Foyer
@OneToMany(mappedBy = "foyer")
@JsonIgnore
private Set<Bloc> blocs;

// Bloc, le fils
@ManyToOne
private Foyer foyer;

Un vers plusieurs, dans un seul sens. Chambre a une liste de Reservation. Reservation n'a pas de champ vers Chambre. Hibernate crée la table chambre_reservations.

// Chambre seulement
@OneToMany
private Set<Reservation> reservations;

Plusieurs vers plusieurs, dans les deux sens. Etudiant est le fils. Reservation possède la liste. La table de jointure s'appelle reservation_etudiants.

// Reservation, le propriétaire
@ManyToMany
private Set<Etudiant> etudiants;

// Etudiant, le fils
@ManyToMany(mappedBy = "etudiants")
@JsonIgnore
private Set<Reservation> reservations;

@JsonIgnore vient de com.fasterxml.jackson.annotation.JsonIgnore. Dans les exemples de ce TP, il empêche Jackson de parcourir les associations dans les deux sens. Il ne détermine pas le côté propriétaire JPA.

ddl-auto=update ne supprime pas automatiquement les anciennes colonnes. Sur une base de TP jetable, tu peux recréer le schéma après avoir sauvegardé ce que tu veux garder. Ne supprime jamais une base contenant des données utiles.
