7. REST et Postman

Le controller reçoit l'appel HTTP et appelle le service. L'adresse est faite de quatre morceaux.

WS REST. Une page du PDF met le context path /foyer. Les URL du chapitre utilisent /tpfoyer. Tu suis application.properties.

0 sur 0

Avant de commencer : c'est quoi une API REST ?

Imagine la réception d'un hôtel : Postman est le client. Le Controller reçoit sa demande, le Service travaille, et le Repository interroge MySQL. La réponse revient souvent sous forme de JSON.

HTTP est le protocole de communication. URL est l'adresse. JSON représente les données, comme {"nomBloc":"A"}.

1. Quatre méthodes à connaître

MéthodeButExemple TP
GETLireTous les blocs ou un bloc
POSTCréerAjouter un bloc avec un JSON
PUTModifierModifier un bloc
DELETESupprimerSupprimer un bloc par ID

2. L'adresse complète

http://localhost:8089 = serveur + port ; /tpfoyer = contexte ; /bloc = classe du controller ; /retrieve-all-blocs = méthode.

Attention : si server.servlet.context-path=/lab dans tes application.properties, utilise /lab dans l'URL. Le contexte /tpfoyer n'est pas universel.

3. Ton premier test dans Postman

  1. Démarre MAMP/MySQL et ton application Spring Boot dans IntelliJ.
  2. Dans Postman, choisis GET et colle http://localhost:8089/tpfoyer/bloc/retrieve-all-blocs, en adaptant le contexte.
  3. Clique sur Send et regarde le code de réponse. [] signifie « liste vide », pas « erreur ».

4. Envoyer un objet JSON

Choisis POST, URL /tpfoyer/bloc/add-bloc, puis Body → raw → JSON dans Postman :

{
  "nomBloc": "A",
  "capaciteBloc": 100
}

Le controller récupère cet objet avec @RequestBody. MySQL peut attribuer automatiquement l'idBloc configuré avec IDENTITY.

5. Les codes de réponse HTTP

  • 200 OK : succès ; c'est souvent le code des méthodes de ce TP.
  • 201 Created : code de création quand le controller est configuré pour le retourner, pas automatique ici.
  • 400 Bad Request : erreur dans les données ou leur décodage.
  • 404 Not Found : URL inexistante, ou ressource absente si l'API gère ce cas.
  • 500 Internal Server Error : exception non gérée, par exemple findById(id).get() sur un élément absent.

Le mini-Postman interactif ci-dessous est une simulation visuelle, pas une vraie connexion à ta base. Fais ensuite ces appels dans Postman.

Les quatre morceaux

http://localhost:8089/tpfoyer/bloc/retrieve-all-blocs

  • 8089 est le port.
  • /tpfoyer est le context path.
  • /bloc est @RequestMapping sur la classe.
  • /retrieve-all-blocs est @GetMapping sur la méthode.

Si un morceau manque, Postman répond 404 alors que l'application tourne.

@RestController
@AllArgsConstructor
@RequestMapping("/bloc")
public class BlocRestController {
    IBlocService blocService;

    @GetMapping("/retrieve-all-blocs")
    public List<Bloc> getBlocs() {
        return blocService.retrieveAllBlocs();
    }

    @GetMapping("/retrieve-bloc/{bloc-id}")
    public Bloc retrieveBloc(@PathVariable("bloc-id") Long id) {
        return blocService.retrieveBloc(id);
    }

    @PostMapping("/add-bloc")
    public Bloc addBloc(@RequestBody Bloc b) {
        return blocService.addBloc(b);
    }

    @DeleteMapping("/remove-bloc/{bloc-id}")
    public void removeBloc(@PathVariable("bloc-id") Long id) {
        blocService.removeBloc(id);
    }

    @PutMapping("/modify-bloc")
    public Bloc modifyBloc(@RequestBody Bloc b) {
        return blocService.modifyBloc(b);
    }
}

Dans ce TP, les méthodes GET par identifiant et DELETE récupèrent l’id dans l’URL avec @PathVariable. Le GET qui liste tous les blocs n’a pas d’id. POST et PUT utilisent un corps JSON avec @RequestBody. Le nom dans l’annotation correspond à bloc-id dans les accolades.

Le JSON

{
  "idBloc": null,
  "nomBloc": "A",
  "capaciteBloc": 100
}

Les noms sont ceux des champs Java : nomBloc, pas nom_bloc.

Avec Jackson 3 dans la configuration du TP, un champ primitif boolean absent peut provoquer un HTTP 400 pendant la désérialisation. La propriété spring.jackson.deserialization.fail-on-null-for-primitives=false modifie ce comportement. L’option la plus claire reste d’envoyer true ou false.

Il n'y a pas de cascade dans ce TP. Tu crées chaque entité avec son propre POST.

Les quatre couches, maintenant que tu les as vues

  1. Postman appelle l'adresse.
  2. Le controller reçoit l'appel et appelle le service.
  3. Le service appelle le repository. Spring a mis le repository dans le service.
  4. Le repository lit ou écrit la table. Hibernate montre le SQL dans la console.
